# رباتیک در پزشکی (Robotics in Medicine)

یک وب‌سایت اطلاع‌رسانی چندصفحه‌ای درباره‌ی کاربرد رباتیک در حوزه‌ی پزشکی، به زبان فارسی (RTL)، همراه با یک فرم تماس و یک نمونه‌ی نمایش داده‌ی JSON در جدول.

## ساختار پروژه

```
robotics-in-medicine/
├── index.html          # صفحه اصلی
├── page2.html          # کاربردها، فواید و چالش‌ها
├── page3.html          # انواع ربات‌های پزشکی (با نمودار Chart.js)
├── page4.html           # فرم ارتباط با ما
├── data.html            # نمایش لیست ربات‌های پزشکی از data.json در جدول
├── data.js              # واکشی AJAX (jQuery) داده از data.json
├── data.json            # داده‌ی نمونه‌ی ربات‌های پزشکی
├── form.html             # فرم نمونه‌ی بازخورد (مستقل از سایت اصلی)
├── css/
│   ├── style1.css ... style4.css
├── js/
│   ├── script1.js ... script4.js
├── package.json
├── package-lock.json
└── .gitignore
```

## اجرای پروژه

چون این پروژه صرفاً فرانت‌اند استاتیک است (فعلاً بدون بک‌اند واقعی — به بخش «مشکلات شناخته‌شده» مراجعه کنید)، برای مشاهده‌ی صفحات کافیست:

```bash
# با هر سرور استاتیک ساده، مثلاً:
npx serve .
# یا فقط index.html را در مرورگر باز کنید
```

اگر بک‌اند Node.js (Express + Mongoose) را کامل کردید:

```bash
npm install
npm run dev   # اجرای سرور با nodemon
# یا
npm start
```

## ⚠️ مشکلات شناخته‌شده / کارهای باقی‌مانده

این‌ها موارد واقعی هستن که قبل از انتشار عمومی یا استفاده‌ی جدی بهتره بهشون رسیدگی بشه:

1. **بک‌اند وجود نداره ولی ازش استفاده شده.**
   `package.json` به `server.js` اشاره می‌کنه (`main`, `npm start`) ولی این فایل در پروژه موجود نیست. همچنین `index.html` مستقیماً از `http://localhost:5000/api/robots` و `http://localhost:5000/api/users` دیتا می‌گیره — یعنی برای هر بازدیدکننده‌ای (یا روی GitHub Pages) این دو جدول همیشه خالی می‌مونن و در کنسول خطا می‌زنن، چون سروری در کار نیست. باید یا `server.js` را با Express/Mongoose بنویسید و مسیرهای `/api/robots` و `/api/users` را پیاده کنید، یا اگر قرار نیست بک‌اند کامل بشه، آن دو بلوک `<script>` را از `index.html` حذف کنید.

2. **دو روش موازی و ناهماهنگ برای نمایش داده‌های ربات‌ها وجود داره:**
   - `data.html` + `data.js` + `data.json`: یک نمونه‌ی کامل و کارکننده که با jQuery AJAX از یک فایل JSON محلی می‌خونه.
   - `index.html`: یک `fetch` جداگانه به یک API لوکال (که وجود نداره) برای همون نوع داده.

   بهتره یکی از این دو روش رو انتخاب کنید (فایل JSON استاتیک ساده‌تره اگه بک‌اند ندارید).

3. **فایل‌های رسانه‌ای (تصاویر و ویدیو) در پروژه موجود نیستند.**
   مسیرهایی مثل `pics/pic1.jpg`, `pics/logo1.jpg`, `pics/pic5.jpg` تا `pic8.jpeg` و `videos/robot-tour.mp4` در HTML/CSS ارجاع داده شدن ولی خود فایل‌ها آپلود نشدن. پوشه‌های `pics/` و `videos/` رو بسازید و فایل‌های واقعی رو داخلشون بذارید، وگرنه تصاویر شکسته و ویدیوی خالی نمایش داده می‌شه.

4. **تگ ویدیو اصلاح شد.** در `page2.html`، ویدیو قبلاً با `<iframe src="....mp4">` نمایش داده می‌شد که برای فایل ویدیویی مستقیم درست نیست (iframe برای embed کردن صفحات دیگه‌ست، نه فایل ویدیو). به `<video controls>` تغییر داده شد.

5. **فرم `form.html` اصلاح شد.** ساختار HTML اشتباه بود (`<table>` بیرون از `<form>` و بدون `<body>`). حالا `<form>` به‌درستی `<table>` رو در بر می‌گیره و تگ `<body>` اضافه شده. توجه کنید که `action="#"` هنوز جایی داده رو ارسال نمی‌کنه — اگه این فرم قراره واقعاً کار کنه، باید یک مسیر بک‌اند (مثلاً همون Express) براش تعریف بشه.

6. **بارگذاری تکراری اسکریپت‌ها در `page3.html` حذف شد.** قبلاً `chart.js` و `script3.js` هم در `<head>` و هم دوباره قبل از `</body>` لود می‌شدن که باعث اجرای دوباره‌ی کد و ساخت نمودار تکراری می‌شد.

7. یک تایپوی جزئی (عدد «2» اضافه بعد از لینک «صفحه اصلی») در `index.html` حذف شد.

8. فایل‌های CSS و JS به پوشه‌های `css/` و `js/` منتقل شدن تا با مسیرهایی که خود فایل‌های HTML (`href="css/..."`, `src="js/..."`) ازشون انتظار دارن مطابقت داشته باشه — در نسخه‌ی آپلودی این فایل‌ها flat بودن و لینک‌ها می‌شکستن.
